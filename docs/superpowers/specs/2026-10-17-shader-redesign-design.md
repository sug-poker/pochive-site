# Pochive サイト シェーダー刷新 設計書

## 目的と背景

Pochive（iOS のポーカー収支管理・ハンド記録アプリ）の紹介サイトを、「かっこいい・スタイリッシュで、他にない」見た目にする。

目指す空気感は「ポーカーをプレイしているテーブルの空気」と「データ管理の近未来感」の両立。既存の配色（深緑のフェルト × ゴールド × クリーム）を土台に、WebGL のフラグメントシェーダーで背景と演出を描く。

GitHub Pages（静的ホスティング）でそのまま動くことが前提条件。

**承認済みモックアップ:** `docs/superpowers/specs/assets/2026-10-17-shader-mockup.html`
（ブレインストーミングの最終版 v5。シェーダーの見た目・動き・パラメータはこれが正。画像は `/files/shot-*.png` を参照しているので、手元で開くときは `public/screenshots/*.png` に読み替える）

## ゴール

1. ページ全体の背面に、1 枚のシェーダー背景（フェルト＋スポットライト＋型押しスート）を固定表示する
2. Hero で「ポーカーを、記録する。」を表す物語演出（配る → 走査して記録 → データがアプリへ流れ込む）を見せる
3. 機能 4 つそれぞれに、内容に対応した演出をスマホの背後に出す
4. セクションの見た目を、シェーダー背景が透けるスタイルに刷新する
5. WebGL が使えない環境・動きを減らす設定・プリレンダリングでも破綻しない

## 非ゴール

- 文言（コピー）の変更、セクションの追加・削除、ページ構成の変更
- プライバシーポリシー・利用規約ページ（`public/privacy-policy`, `public/terms`）の見た目変更
- デプロイワークフロー（`.github/workflows/deploy.yml`）の変更
- three.js などの 3D ライブラリの導入

## アンチゴール（技術的に動いても失敗とみなすもの）

- 本文や見出しが背景演出に負けて読みにくくなる
- WebGL 非対応端末で、背景が真っ白・真っ黒など表示が崩れる
- スマホでバッテリーや発熱が目に見えて悪化するほど重い
- プリレンダリング（`scripts/prerender.mjs`）やハイドレーションが壊れる
- 演出がサイトのテーマカラー（深緑・ゴールド・クリーム・くすんだ緑灰）から外れる。赤・白などテーマ外の色を使わない

## 決定事項（ユーザーと合意済み）

### 背景の土台（ページ全体）

- ページ全体の背面に `position: fixed` の canvas を 1 枚置き、全セクション共通で描く
- 構成要素:
  - フェルトの質感（fbm ノイズ）
  - 頭上のスポットライト（マウスに追従）
  - 型押しのスート柄（光が当たった所だけうっすら浮かぶ）
  - グリッドの交点がときどきスートの形で光る演出（Hero 以外で、光の当たる範囲だけ控えめに）
- **グリッド上を走る線（パルス）は入れない**（ユーザーが明示的に削除を希望）
- **チップは入れない**（ユーザーが明示的に削除を希望）
- **テーブルの楕円ラインは入れない**（意味が伝わりにくいため Hero から外した）

### Hero 演出：スマホを囲むテーブルの輪郭（2026-10-17 再改訂）

**承認済みモックアップ:** `docs/superpowers/specs/assets/2026-10-17-hero-abstract-mockup.html` の案 A（`motifTable`）。見た目・定数はこれが正。

経緯: カード 7 枚の走査 → 線画テーブルで 1 ハンドをプレイする場面描写、と変えてきたが、ユーザーが「具体的すぎて機能紹介のシェーダーとバランスが悪い」と判断した。そのため、機能セクションと同じ作法（スマホの背後に金の線画モチーフを 1 つだけ置く）に揃える。

- **モチーフ:** Hero のスマホを囲むレーストラック型のテーブルの輪郭だけを描く。中身は、内側の縁、外側のレール、点線のベッティングライン。座標はスマホの高さを単位にした局所座標で、機能の演出と同じ扱い。席・チップ・カード・ポジション名・ハンドの進行は描かない
- **動き:** 縁を 3 つの光の点がゆっくり巡る（尾を引く）。3.2 秒ごとに 1 つが縁を離れてスマホへ落ちる
- **スマホの縁は光らせない:** 光が届いたときにスマホの縁を光らせる演出は、ユーザーが「ちょくちょく光るのが気になる」として外した
- **スマホ画面:** 実際のスクリーンショット `hands.png` の 1 枚だけを表示する。収支画面への切り替えはしない（Claude の判断。1 ハンドの区切りがなくなったため）
- **レイアウト:** デスクトップは「左：文字／右：スマホ」。モバイルは「文字（タイトルが一番上）→ スマホ画像」の縦並び（スマホ画像の幅 240px、ユーザー判断）
- **モバイルの輪郭:** 縦画面では横長の輪郭が左右で切れて読み取れなかったため（ユーザー指摘）、輪郭を縦向きにしてスマホ画像を一回り大きく囲む形にする（直線部の半長 .2、端の半径 .34、スマホの高さ単位）。輪郭が CTA に重ならないよう、文字とスマホ画像の間隔を 72px にする
- 明るさと線の細さは機能セクションの演出に揃える。色はテーマ内だけ

スクロールで Hero を離れると、Hero の演出はフェードアウトする（`heroFade`）。

### 機能セクションの演出

各機能のスマホの背後に、内容に対応した演出を出す。演出はそのスマホの位置に追従し、スマホが画面中央に近づくほど濃くなる。

| 機能 | 演出 |
|---|---|
| 01 セッション記録 | スマホを囲む時計の文字盤。経過時間を表す金の弧がゆっくり一周する |
| 02 ハンド記録 | スマホの背後に 5 枚のカードが扇状に並び、フロップ → ターン → リバーの順に光る |
| 03 バンクロール・統計 | 収支グラフの線が、スマホから説明文の下へ伸びながら描かれる（塗りと薄い横グリッド付き） |
| 04 遠征管理 | スマホの背後で回るワイヤーフレームの地球儀と、説明文の方向へ渡る点線の航路＋飛行機の光点 |

- グラフと航路は、スマホから説明文の側へ伸ばす。左右交互のレイアウトに合わせて向きを反転させ、画面端で切れないようにする
- 機能セクションでは、スポットライトが画面中央に最も近いスマホを自動で照らす。それ以外の場所ではマウスに追従する

### セクションのスタイル刷新

モックアップどおりにする。

- 各セクションの不透明な背景（`.features` と `.contact` の `var(--surface)`）を外し、シェーダー背景が透けるようにする
- 見出しの上に小さな英字ラベル（`FEATURES` / `PRICING` / `CONTACT`）。ゴールド、字間を広く取る
- 機能に番号ラベル（`01 / SESSION`、`02 / HAND`、`03 / BANKROLL`、`04 / TRIP`）。等幅フォント、ゴールド
- 機能の区切り線は、ゴールドの極薄ライン
- 料金カードと比較表は、すりガラス風（半透明背景＋`backdrop-filter: blur`）。おすすめプランは金の縁を光らせる
- 料金カードの箇条書きの頭は `✓` から `♠` に変える
- スマホフレームは、ゴールドの細い縁＋ほのかな金のグロー
- Nav はスクロール時に半透明＋ぼかし＋ゴールドの極薄下線
- App Store ボタンに金のほのかなグロー

### モバイル（ユーザーと合意済み）

- **配置（幅 768px 以下）:** Hero は既存どおり縦並び（スマホが上、文字が下）。カードの場の位置はデスクトップの座標固定ではなく、Hero 内の要素（例: 文字ブロックの下、またはスマホの下端付近）を基準に置き、画面幅に収まる大きさに縮める。機能の演出は、スマホが中央寄せになるので左右に伸ばさず、スマホを中心に対称に収める（グラフと航路はスマホの下側へ伸ばす）
- **進め方:** モバイル版のモックアップは作らず、上記の方針で実装してから実機で見て調整する
- **軽量化を優先:** スマホではモックアップと見た目が多少変わってもよいので、軽さを優先する。調整の順は、(1) 描画解像度を 1 倍に抑える、(2) フェルトの fbm のオクターブ数を減らすなどして質感の計算を軽くする、(3) それでも重ければ 30fps に落とす
- **実機確認:** 最終確認はユーザーが自分の iPhone で行う

### 技術方針

- 素の WebGL（WebGL1）。ライブラリは追加しない
- シェーダーはブラウザ内だけで動くので、GitHub Pages 上で追加の設定は不要

## 制約

- **プリレンダリング:** `scripts/prerender.mjs` が `entry-server.tsx` を Node 上で描画する。canvas と WebGL の初期化は `useEffect` 内（クライアントのみ）で行い、サーバー描画時に `window` や `document` に触れない。プリレンダー結果とハイドレーション結果の DOM が一致すること
- **フォールバック:**
  - WebGL が取得できない場合: canvas を出さず、CSS だけでフェルト風の背景（深緑のグラデーション＋ビネット）を表示する
  - `prefers-reduced-motion: reduce` の場合: アニメーションループを回さず、静止した 1 フレームを描く。Hero は輪郭と光の点が描かれた静止状態で止める。スクロールやリサイズのときだけ再描画してよい
- **パフォーマンス:**
  - devicePixelRatio の上限は 1.5（モックアップと同じ）。モバイルは 1（「モバイル」の項を参照）
  - タブが非表示（`document.hidden`）のときは描画を止める
  - 毎フレームの `getBoundingClientRect` は対象 5 要素（Hero のスマホ＋機能のスマホ 4 つ）に限る
- **アクセシビリティ:** canvas は `aria-hidden="true"` にし、ポインタイベントを受けない（`pointer-events: none`）
- **既存の依存:** `@pochive/plans` からの料金データ表示はそのまま使う

## ビルダーに任せる部分

- コンポーネント分割とファイル構成。参考案: `ShaderBackground` コンポーネント、シェーダーソースを `src/shaders/*.glsl` に置いて Vite の `?raw` で読み込む
- React から canvas へスマホ要素の位置を渡す方法（ref、`data-*` 属性、querySelector など）
- シェーダーの細かな定数調整。モックアップの見た目から大きく外れない範囲で
- CSS の書き方（既存の `index.css` に追記するか分割するか）

## 私（Claude）の判断で決めた点（ユーザー未確認）

- **タッチ端末:** マウスがないので、スポットライトは Hero ではスマホ付近に置く。機能セクションでは、画面中央のスマホを照らす挙動をそのまま使う
- **スマホフレーム:** 既存のノッチ風の装飾（`::before` のバー）は外し、モックアップの「細い金縁＋角丸」にする
- **Hero のカードの位置（デスクトップでも）:** ビューポート固定座標ではなく、Hero の文字ブロック（CTA の下）を基準に置く。基準要素の位置とサイズを機能の演出と同じ方法でシェーダーへ渡し、スクロールすると文字と一緒に動くようにする。文字とは重ねない
- **スタイル刷新の範囲:** 「セクションのスタイル刷新」に列挙した項目に、CSS だけで済む次の差分を加える。セクションの上下余白 120px、フッターの金の極薄上線、スマホフレームを画像サイズ＋内側余白で決める（固定サイズと `object-fit: cover` をやめる）。JSX の構造（料金カードのバッジ位置、年額の位置、表ヘッダーの表記など）は変えない。モックアップとの差はこの範囲に限る
- **`.superpowers/` の除外:** ブレインストーミング用のフォルダなので `.gitignore` に追加する

## 検証方法

- `npm run lint` と `npm run build`（プリレンダーを含む）が通ること
- `npm run preview` で表示し、デスクトップ幅（1280px 程度）とモバイル幅（390px 程度）で以下を目視確認する
  - Hero のループ（配る → 走査 → 粒がスマホへ）
  - 機能 4 つの演出が、それぞれのスマホに追従して出ること
  - 本文の可読性
- DevTools のレンダリング設定で `prefers-reduced-motion` をエミュレートし、静止表示になること
- WebGL を無効化した状態（例: Chrome の `--disable-webgl`）で、CSS のフォールバック背景になること
- ブラウザのコンソールにシェーダーのコンパイルエラーが出ないこと
